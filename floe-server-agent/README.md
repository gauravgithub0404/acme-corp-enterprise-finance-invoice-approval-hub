# Floe Server Agent Daemon (On-Premise / Bare-Metal Host)

The **Floe Server Agent** is a lightweight daemon that runs on your bare-metal or virtual host (e.g., **Laptop 2** connected via Tailscale IP `100.79.73.17`). It receives zip bundles generated by Floe Studio, executes Docker Compose pipelines, manages local PostgreSQL databases, and enforces health checks.

---

## 📋 Prerequisites on Laptop 2

1. **Docker Desktop & Docker Compose** (ensure Docker daemon is running)
2. **Node.js 18+** & `npm`
3. **Tailscale** installed and connected (e.g., IP: `100.79.73.17`)

---

## 🚀 Quickstart (Running on Laptop 2)

### Option A: Running with `tsx` (Development / Immediate Run)

1. Open PowerShell or Terminal in the `floe-server-agent` directory:
   ```bash
   cd floe-server-agent
   npm install
   ```

2. Start the daemon on port `4000` (or your preferred agent port):
   ```bash
   npm run dev
   ```

   *Required: a shared secret.* This daemon extracts uploaded ZIP artifacts and
   runs `docker compose up --build` on them, so it must never be reachable
   without authentication -- even on a private Tailscale network. Generate a
   long random value and set it as `AGENT_SHARED_SECRET`; every request must
   then include `Authorization: Bearer <secret>`. If you omit it, the daemon
   refuses to start unless you explicitly set `ALLOW_INSECURE_AGENT=true`, in
   which case it binds to `127.0.0.1` only (not reachable over Tailscale/LAN).

   ```bash
   # Windows PowerShell
   $env:AGENT_PORT="4000"
   $env:TAILSCALE_IP="100.79.73.17"
   $env:AGENT_SHARED_SECRET="<generate with e.g. openssl rand -hex 32>"
   npm run dev

   # Linux / macOS Bash
   AGENT_PORT=4000 TAILSCALE_IP=100.79.73.17 AGENT_SHARED_SECRET="$(openssl rand -hex 32)" npm run dev
   ```

3. Verify the agent is online (all requests need the bearer token):
   ```bash
   curl -H "Authorization: Bearer $AGENT_SHARED_SECRET" http://100.79.73.17:4000/api/v1/health
   # Returns: {"status":"online","agent_version":"1.0.0","docker_ready":true,...}
   ```

## 📡 REST API Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/v1/health` | Agent status, OS info, and Docker availability |
| `GET` | `/api/v1/system` | Live CPU, Memory, Disk, and container telemetry |
| `POST` | `/api/v1/deploy` | Unpack artifact ZIP, execute Docker Compose, run health check |
| `GET` | `/api/v1/deployments/:id` | Full deployment state machine progress & logs |
| `GET` | `/api/v1/deployments/:id/logs` | Real-time deployment build logs |
| `POST` | `/api/v1/apps/:appId/stop` | Stop running containers for the specified app |

---

## 🔄 Deployment Lifecycle State Machine

1. `deployment_requested` → Job registered in memory
2. `artifact_uploaded` → ZIP extracted to `deployed_apps/<domain>_<appId>`
3. `container_building` → `docker compose up --build -d` invoked
4. `services_started` → PostgreSQL & Backend containers booted
5. `health_check_running` → Health probe sent to `http://localhost:4000/api/health`
6. `healthy` → Verified 200 OK with database connection; ready for live traffic!
